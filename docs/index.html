How it works

    
Prose can be drifted past. A gate cannot.

    
Everything is plain files in your repository. No service, no telemetry, no runtime dependency.

    

      

        

        
Process sized to the change

        
The agent names a tier before it starts. A typo is edited and verified. A feature gets a plan with acceptance criteria and waits for you.

        
agent  Tier: S — bug fix in cart total, single file.

      

      

        

        
Rules compiled into enforcement

        
One policy file becomes Claude Code permissions, a guard hook, git hooks and a CI check. Deny always wins.

        
allow    npm test*
confirm  npm install *
deny     git reset --hard*

      

      

        

        
Your stack, detected

        
It reads your manifests, lockfile and CI to learn the real test, lint and build commands instead of assuming them.

      

      

        

        
Approval is a record

        
Silence is not consent. Feature work starts only after you approve that specific plan, and the approval is written down.

      

      

        

        
A checker, not a score

        
vibe check names the file and the line: a secret, a debug call, a file outside the task, a dependency nobody explained.

Install

    
One command. Nothing of yours is overwritten.

    
Needs Node 18 or newer, bash and git. On Windows use WSL or Git Bash.

    

      

        
        
        
      

      

        
$cd your-project && npx vibediscipline init

        
Detects Laravel, Node or Python and picks a matching permission list. Your AGENTS.md, CLAUDE.md, Claude Code settings and git hooks are kept, and VibeDiscipline is added beside them. Preview with --dry-run.

      

      

        
$npx vibediscipline new my-app

        
Asks for a backend (Laravel, Next.js, Django, NestJS) and a frontend (React, Vue, Angular), runs that framework's own scaffolder, then installs VibeDiscipline in the result. No framework code ships in this package, so a new project is always what the framework ships today.

      

      

        
$npx vibediscipline init --skills-only

        
Copies .agent/skills/ and nothing else: the behaviour without the enforcement. In Claude Code the same is available as a plugin.

Commands

    
Eight commands. You will use three.

    
Run any of them as npx vibediscipline <command>. Installed globally, the short name is vibe.

    

      
new
Create a project with its framework's scaffolder, with VibeDiscipline in it.

      
init
Install into an existing project.

      
doctor
Check the installation and print the fix for each problem.

      
upgrade
Refresh skills and scripts. Your config, permissions and state stay.

      
check
Scan the diff for secrets, debug leftovers, scope creep, missing tests.

      
compile
Rebuild settings, guard hook and git hooks from the policy.

      
methodology
Show or set agile, waterfall or hybrid.

      
uninstall
Remove it. Your own files are kept, and it asks first.

Scope

    
What it covers today, and what it does not.

    

      
Works now

        
    
          
  • Skills, tiers and git hooks with any agent that reads AGENTS.md

  • Enforced permissions and the guard hook in Claude Code
    • 
          
  • Permission lists for Laravel, Node and Python, plus a generic fallback

  • An agent that stops to ask delivers nothing in an unattended run

Questions

    
Before you install.

    

      
Does it slow the agent down?
Not for small work: a typo or a bug fix has no plan and no document. A feature gets one stop, where you approve a plan. That stop is the point.

      
Will it overwrite my files?
No. An existing AGENTS.md keeps its content with VibeDiscipline added above it, existing Claude Code permissions are left alone, and an existing git hooks path is not replaced. Uninstall puts your files back as they were.

      
Is my code sent anywhere?
No. It is files and local scripts in your repository, with zero dependencies.

      
Can I change the rules?
Yes. The policy is .agent/permissions.yml and the settings are .agent/config.yml, both plain text. An upgrade never touches them.

      
How much context does it use?
AGENTS.md is about 70 lines and is the only file loaded every session. Skills are read when a task calls for one.
