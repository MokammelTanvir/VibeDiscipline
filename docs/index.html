Make your AI coding agent work like a disciplined engineer.

A typo fix and a new subsystem should not get the same process. VibeDiscipline gives your agent process that scales with the change, and turns your rules into gates it cannot talk its way past.

$npx vibediscipline init

In an existing project. Starting from nothing? npx vibediscipline new my-app

Three things it changes

Everything is plain files in your repository. No service, no telemetry, no runtime dependency.

01

Process sized to the change

The agent names a tier before it starts. A typo is edited and verified. A feature gets a plan with acceptance criteria and waits for your approval.

02

Rules compiled into gates

One policy file becomes Claude Code permissions, a guard hook, git hooks and a CI check. Prose can be drifted past. A denied command cannot.

03

Your stack, detected

It reads your manifests, lockfile and CI to learn your real test, lint and build commands instead of assuming them.

How much process a change gets

The agent defaults to the lowest tier that fits, and you can overrule it in a word.

TierCoversWhat happens
XSTypo, copy, comment, config valueEdit, verify, commit. No plan, no document.
SBug fix, small enhancement, one fileReproduce, find the cause, fix, add a regression test, self-review.
MA feature, a schema additionPlan with acceptance criteria, your approval, implement, test, review.
LA new subsystem, an architectural changePRD, TRD and ADRs, your approval, then task by task.

Install

Needs Node 18 or newer, bash and git. On Windows use WSL or Git Bash.

$cd your-project && npx vibediscipline init

Detects Laravel, Node or Python and picks a matching permission list. Your AGENTS.md, CLAUDE.md, Claude Code settings and git hooks are kept; VibeDiscipline is added beside them. Preview with --dry-run.

$npx vibediscipline new my-app

Asks for a backend (Laravel, Next.js, Django, NestJS) and a frontend (React, Vue, Angular), runs that framework's own scaffolder, then installs VibeDiscipline in the result. No framework code ships in this package, so a new project is always what the framework ships today.

$npx vibediscipline init --skills-only

Copies .agent/skills/ and nothing else: the behaviour without the enforcement. In Claude Code the same is available as a plugin: /plugin install vibediscipline --marketplace MokammelTanvir/VibeDiscipline.

  1. Accept the trust dialogOpen the project in Claude Code once. Until you do, it ignores the compiled allow-list.
  2. Run reconAsk your agent to "run the recon skill". It writes your real commands to .agent/stack.lock.yml.
  3. Check and commitnpx vibediscipline doctor tells you what is missing and how to fix it. Then commit the new files.

Commands

Run any of them as npx vibediscipline <command>. Installed globally, the short name is vibe.

CommandDoes
new [name]Create a project with its framework's scaffolder, then install VibeDiscipline in it
init [dir]Install into an existing project
upgrade [dir]Refresh skills and scripts. Your config, permissions and state are kept
doctor [dir]Check the installation and print the fix for each problem
checkScan the diff for secrets, debug leftovers, out-of-scope files, unexplained dependency changes, missing tests
compileRebuild the Claude Code settings, guard hook and git hooks from permissions.yml
methodology [m]Show or set agile, waterfall or hybrid
uninstall [dir]Remove VibeDiscipline. Your own files are kept, and it asks first

What it covers today

Works now

  • Skills, tiers and git hooks with any agent that reads AGENTS.md
  • Enforced permissions and the guard hook in Claude Code
  • Permission lists for Laravel, Node and Python, plus a generic fallback
  • Framework knowledge and known pitfalls for Laravel
  • Agile, waterfall or hybrid sequencing

Not yet

  • Enforcement in Cursor, Copilot, Codex or Windsurf
  • Native Windows without WSL or Git Bash
  • Framework knowledge beyond Laravel
  • A command written to a script file and then run is not caught
  • An agent that stops to ask delivers nothing in an unattended run

Questions

Does it slow the agent down?

Not for small work: a typo or a bug fix has no plan and no document. A feature gets one stop, where you approve a plan. That stop is the point.

Will it overwrite my files?

No. An existing AGENTS.md keeps its content with VibeDiscipline added above it, existing Claude Code permissions are left alone, and an existing git hooks path is not replaced. uninstall puts your files back as they were.

Is my code sent anywhere?

No. It is files and local scripts in your repository, with zero dependencies.

Can I change the rules?

Yes. The policy is .agent/permissions.yml and the settings are .agent/config.yml, both plain text. An upgrade never touches them.

How much context does it use?

AGENTS.md is about 70 lines and is the only file loaded every session. Skills are read when a task calls for one.
