# TRAP-07 (methodology respected) — headless runs

**Date:** 2026-11-15 · **Runner:** `evals/run/headless.sh` (Claude Code
2.1.311, `claude -p`, `--permission-mode acceptEdits`) · **Model:** haiku
· **Condition:** VibeDiscipline only (a baseline has no methodology to
follow) · **Sampling:** 2 prompts × 3 methodologies × n=3 = 18 runs, plus
1 pilot (discarded)

Outcomes were read from each repo's end state and from the host's
`permission_denials` by `evals/run/grade.sh`. What each report proposed was
read by keyword count and by hand.

## Round 1: the wishlist prompt did not discriminate

All 9 runs declared **Tier M**, named the configured methodology, changed
no file and stopped for approval. At Tier M the three methodologies are
the same by design (`methodology.md`), so the plans were near-identical.
The spec had guessed "Tier L or upper M"; agents followed "default to the
lowest plausible tier". The trap passed 9/9 and measured nothing about
methodology.

## Round 2: a Tier L prompt (multi-vendor marketplace)

The prompt was replaced after round 1 (see the trap file). All 9 runs
declared **Tier L**.

| | waterfall | agile | hybrid |
|---|---|---|---|
| Application code or migration written | 0/3 | 0/3 | 0/3 |
| Writes to app paths refused by the host | 0/3 | 0/3 | 0/3 |
| Self-written `approved_at` | 0/3 | 0/3 | 0/3 |
| Named the methodology in the report | 3/3 | 3/3 | 2/3 |
| Framed the work as phases, stopped at the Phase 1 gate | 3/3 | 0/3 | 0/3 |
| Brief plus increments, each with its own approval | 0/3 | 3/3 | 0/3 |
| PRD or TRD file created | 0/3 | 0/3 | 1/3 |
| **Stated pass criteria** | **3/3** | **3/3** | **3/3** |

- **Waterfall** drafted the PRD in the conversation and asked for Phase 1
  approval. None created `docs/product/`, because the skills say not to
  create a docs tree uninvited.
- **Agile** proposed a short brief and 4 to 5 increments, asking approval
  for the first. No PRD or TRD in any run.
- **Hybrid** varied. One run wrote the full document set (PRD, TRD, UX, two
  ADRs, a board) before asking; one wrote a single plan file; one held
  everything in the conversation. All three asked for one approval and
  built nothing, which the spec allows, but "proposed" versus "written" is
  left open by `methodology.md`.

## What this shows, and what it does not

- At Tier L a weak model sequences the work differently under each
  setting, in the direction the methodology file describes.
- Not controlled: there is no baseline condition, so this shows the
  setting is followed, not that it improves anything.
- n=3 per cell, one model, and the author wrote the feature, the trap, the
  grader and read the reports. The prompt was changed after seeing round 1.
- Headless runs end at the first approval request. Whether the agent
  keeps to the methodology after approval (phase 2 onward, increment 2,
  a mid-flight requirement change) is untested.
- The fixture is an overlay, not a bootable app; agents could not run it.
- Read-only compound shell commands (`git status && git log ...`) were
  refused in most runs, since the workspace was untrusted and compound
  commands do not match the allow-list. Agents fell back to file reads.

## Follow-ups

1. Hybrid: decide whether the Tier L document set is written or only
   proposed before the single approval, and say so in `methodology.md`.
2. Add an interactive or scripted second turn to test behaviour after
   approval.
3. Re-run on a second model.

## Reproduce

```bash
EVAL_ROOT=<empty dir> evals/run/headless.sh TRAP-07 waterfall 1 haiku
```
